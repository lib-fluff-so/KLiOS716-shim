# v0.9.3 notes

- **XNU framebuffer base fixed.** The panel scans out a page that starts 1230 rows into the reserved
  region at 0xFDFFF000 (`src/console.c VISIBLE_OFFSET`, observed since v0.5). v0.9.2's XNU path passed
  0xFDFFF000 in `boot_args.Video.v_baseAddr` and in the ADT `kl7-fbcon` node, so XNU would have drawn
  above/over the visible page. Both now use 0xFDFFF000 + 1230*4352 = **0xFE519E00** (1080x2436, stride 4352,
  size 4352*2436, ends 0xFEF36200). Shim logic otherwise unchanged; not re-run on hardware.
- **XNU kernel delta** in `xnu/patches-kl7/` (applies after ios-sweet `xnu/patches/`; see XNU-PATCH-PORT-PLAN.md).
- `tools/kl7-xnu-tree.sh` builds the patched source tree locally for review (no compile, macOS only).
- **ramoops mirror for XNU** (`xnu/patches-kl7/0103`): every byte on the framebuffer console also goes into the ramoops console zone
  (ADT node `kl7-ramoops`, 0x480EF000+0x40000, generated by mkadt_kl7.py), continuing the shim's ring. Read it from Android with
  `adb exec-out su -c 'cat /sys/fs/pstore/console-ramoops-0'`. Works only across a WARM reset (PSCI reset / watchdog); a power-key
  cold reset may lose DRAM. Not compiled in the full tree yet; the new block syntax-checks standalone.
